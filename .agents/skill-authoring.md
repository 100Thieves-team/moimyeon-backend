# 스킬 작성·평가 규약

스킬을 신설하거나 description·절차를 고칠 때 따른다. 근거: Claude Code 공식
스킬 문서(code.claude.com/docs/ko/skills)의 "Skills 평가 및 반복" +
우리 측정 프로토콜(.worklog/MOI-474/decisions.md DR-012·017).

## 작성

- **description은 유일한 트리거 메커니즘이다.** 무엇을 하는지 + 언제 쓰는지 +
  쓰지 않는 경우(경쟁 스킬로 넘길 조건)를 함께 쓴다. 주요 사용 사례를 앞에
  둔다 — 스킬 목록은 항목당 1,536자에서 잘린다.
- **본문은 간결하게.** 호출되면 그 내용이 세션 내내 컨텍스트에 남아 매 줄이
  반복 비용이다. 왜보다 무엇을 할지 쓰고, 긴 참조는 `references/`로 뺀다
  (공식 상한 500줄, 우리 lint 경고선 150줄).
- **진행 규칙을 인라인한다** — 체크포인트, 재시도·수정 상한, plan.md 초기
  생성·재실행 분기. 공유 문서 참조 대신 각 스킬에 둔다 (DR-020).
- 작성 후 `python3 .agents/gates/lint_skills.py`를 통과해야 한다.

## 평가 — 두 가지를 따로 측정한다

트리거되는 것은 Claude가 스킬을 찾았다는 뜻이지 의도대로 작동했다는 뜻이
아니다. 호출 여부와 출력 품질은 별개다.

### 1. 트리거 (필수)

1. `.agents/evals/trigger/{스킬}.tsv`에 양성·음성·경계 프롬프트를 쓴다.
   음성은 "명백히 무관한 요청"이 아니라 **경쟁 스킬이 정답인 near-miss**여야
   시험 가치가 있다. 하네스 자체를 소재로 삼지 않는다(감지 오염).
2. 격리 워크트리에서 측정한다 — **새 세션이어야 한다.** 스킬을 작성한
   세션의 잔여 컨텍스트가 지침의 간극을 가린다.

   ```bash
   .agents/evals/run.sh trigger claude 1 <워크트리> <스킬명>
   ```

3. `python3 .agents/evals/score.py <raw_dir> <스킬명>`로 확정 집계한다
   (경로 grep은 오탐을 낸다 — 호출 이벤트만 센다).
4. **실패분만 고치고 그 프롬프트만 재측정한다** (DR-017 경량 프로토콜).
   통과분 재실행은 하지 않는다.

### 2. 출력 품질 (스킬 가치가 불확실할 때)

같은 과제를 스킬 있음/없음으로 실행해 산출물을 비교한다. 스킬을 끄는 방법은
`.claude/settings.local.json`의 `skillOverrides`다.

```json
{ "skillOverrides": { "대상-스킬": "off" } }
```

과제는 `.agents/evals/ab/`에 둔다. 정량 판정이 가능하면 assertions를,
아니면 사람 비교로 판정한다.

판정 항목에 **"요구사항의 모호점이 승인 전에 드러났는가"를 반드시 넣는다**
— 실측상 스킬의 가치는 코드 품질(빌드·테스트 통과)이 아니라 여기서 났다
(DR-028). 품질 지표만 보면 Without이 이기는 경우가 있고, 그 사실도 함께
기록한다.

## 하지 않는 것

- 풀 매트릭스 측정(전 스킬 × 전 프롬프트 × 다회 반복) — 토큰 소모의 원인은
  케이스가 아니라 배치 크기다 (DR-017).
- 트리거가 실패하지 않았는데 description을 "개선"하기 — 검증된 베이스라인만
  무효화한다.
