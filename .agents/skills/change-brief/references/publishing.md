# 설명 자료 게시

내용 계약은 SKILL.md에 있고, 이 문서는 게시 수단에 따른 차이만 다룬다.

## 선택

1. 연결된 도구로 Claude Artifact를 만들고 팀에 공유할 수 있으면 우선 사용한다.
2. 지원되지 않으면 같은 접근 범위의 다른 공유 문서를 사용한다. 저장소 Markdown은
   별도 서비스 없이 리뷰어가 열 수 있는 대안이다. Mermaid 표시도 확인한다.
3. 게시 수단이 전혀 없으면 내용과 그림을 먼저 완성하고 게시·주소 확인만 요청한다.
   원 작업의 공유 범위를 임의로 넓히지 않는다.

## 저장소 Markdown

- PR 생성 전 원문을 change-brief.md에 커밋한다. push 후 GitHub에서 파일을 확인하고
  해당 커밋의 permalink를 PR 본문에 넣는다. 브랜치 삭제 뒤에도 읽을 수 있게 한다.
- permalink는 PR 본문에서 관리한다. worklog·docs에는 커밋 해시나 PR/CI 상태를
  복제하지 않는다. 원문 파일이 게시물 자체이므로 자기 URL을 기록하기 위한
  추가 커밋을 만들지 않는다.
- 렌더링 화면과 원문의 내용이 맞는지 확인한다. Markdown 파일이 존재해도 접근
  권한이나 Mermaid 렌더링을 확인하지 못했다면 그 검증은 미완료로 보고한다.

## PR 이후 수정

- 외부 Artifact/공유 문서는 같은 문서를 갱신하고 링크·표시를 재확인한다.
- 저장소 worklog 스냅샷은 PR 후 동결한다. 수정한 설명·시퀀스는 PR 본문의 공유
  설명에 직접 반영하고, 기존 링크는 “최초 설명”으로 구분해 낡은 문서를 최신으로
  소개하지 않는다. 최신 설명의 공유 주소는 PR URL이다. 초안·검증 증거는 저장소
  밖 임시 파일로 다룬다. 이 경로는 리뷰 반영을 위한 PR 본문 갱신에만 사용한다.
