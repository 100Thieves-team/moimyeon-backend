# issue-context — 이슈 컨텍스트 수집

[execution-policy.md](../../execution-policy.md)·[security-policy.md](../../security-policy.md)를 따른다.
`worklog/{이슈키}/context.md`가 이미 있으면 처음부터 다시 만들지 말고
빠진 부분만 보강한다.

## 절차

1. Linear에서 이슈 본문과 커멘트를 조회한다.
2. 이슈 본문에 위키·문서 링크가 있으면 그것부터 읽는다.
3. 사용 가능한 도구 중 팀 위키 MCP가 있으면 이슈 주제로 검색한다.
4. Notion에서 관련 PRD를 찾는다 — 이슈에 링크가 있으면 우선, 없으면
   이슈 제목·도메인 키워드로 검색한다.
5. 관련 코드 위치를 탐색한다: 해당 도메인 패키지, 유사 기능의 기존 구현,
   관련 테스트.
6. `worklog/{이슈키}/context.md`를 작성한다.
7. 요구사항의 모호점·미결정 사항이 보이면 `worklog/{이슈키}/tbd.md`에
   기록한다 (형식: [worklog/README.md](../../../worklog/README.md)).

## context.md에 담을 것

- 이슈 요약 한 단락 + 이슈·PRD·위키 링크
- 요구사항 핵심 — PRD 발췌는 링크와 함께 최소로
- 관련 코드 위치 (파일 경로 + 한 줄 설명)
- 이 작업의 경계 (하지 않는 것)

## 하지 않는 것

- 구현·설계 결정 — 워크플로우 스킬의 몫이다.
- PRD 전문 복사 — 컨텍스트를 잠식한다. 링크와 필요한 발췌만.
- 이슈·PRD를 찾지 못하면 추측으로 채우지 말고 그 사실을 보고하고 멈춘다.
- 이슈가 "제목 + 한 줄" 수준으로 빈약하면 그대로 진행하지 않는다. 부족한
  항목(목적 / 무엇을 하려는지 / 어느 부분과 관련 / 필요한 컨텍스트)을 짚어
  사람에게 보완을 요청한다 — 이슈 품질도 하네스의 일부다.
