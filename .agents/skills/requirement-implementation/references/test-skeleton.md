# service 테스트 스켈레톤 작성 요령

목적: PRD의 요구사항 문장을 실행 가능한 스펙으로 바꾼다. 테스트 이름만 봐도
요구사항 목록이 재구성돼야 한다.

## 변환 규칙

- 요구사항 문장 하나 → 테스트 하나 이상. 문장에 조건("~까지만", "~인 경우")이
  있으면 경계의 양쪽을 각각 테스트로 만든다.
- 테스트 이름은 요구사항의 자연어를 유지한다.
  예: "모임 시작 24시간 전까지만 취소할 수 있다" →
  `참여 취소는 모임 시작 24시간 전까지 가능하다`,
  `모임 시작 24시간 이내에는 참여 취소가 거부된다`.
- 실패 케이스는 기대 에러 코드까지 검증한다 (`docs/conventions/errors.md`).
- 태그·베이스 클래스는 `docs/conventions/testing.md`의 분류를 따른다.
  회귀를 막을 검증을 `develop` 태그에 두지 않는다 (PR CI는 `test`만 돈다).

## 스켈레톤 형태

- given-when-then 골격과 검증 대상만 작성하고 본문은 비워둔다
  (컴파일되지 않아도 된다 — 이 단계 산출물은 스펙이지 코드가 아니다).
- PRD에 없는 시나리오를 임의로 추가하지 않는다. 필요해 보이면 tbd.md에
  기록하고 사람에게 묻는다.
