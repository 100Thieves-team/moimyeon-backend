# worklog 기록 양식

파일 계약은 [.worklog/README.md](../../../../.worklog/README.md) 참조.

## decisions.md 항목

```markdown
## {결정 한 줄}
- 날짜: YYYY-MM-DD
- 내용과 이유: {무엇을 왜 그렇게 했나 — 코드만 봐서는 알 수 없는 배경}
- 대안: {검토했다 버린 것, 이유}
```

코드로 표현되는 내용은 적지 않는다. "왜"만 적는다.

## tbd.md 항목

```markdown
- [ ] {모호점 한 줄} — 배경: {어디서 막혔나}. 관련 명세: {주소 또는 비대상}. 결정 근거: {합의/확인 필요}. 해결: {원본 반영·확인 결과 또는 미완료}
```

구현을 막는 결정이면 기록 후 사람에게 묻는다. 필요한 명세 갱신은 절대로 후속
TODO로 넘기지 않고 현재 작업에서 해결한다. 독립적인 작업은 진행할 수 있지만
필수 갱신이 남은 상태로 해당 단계·PR 생성·리뷰 대응 완료를 선언하지 않는다.
