# issue-context 트리거 세트

주의: 이 스킬은 워크플로우 스킬이 명시 경로로 호출하는 **정상 경유 경로**가
있다 (예: requirement-implementation 2단계). 따라서 "구현해줘"류 프롬프트에서
issue-context가 읽히는 것은 오호출이 아니다 — 그런 케이스는 경계로 분류하고,
음성은 이슈 컨텍스트 수집이 아예 불필요한 요청으로만 구성한다.

러너 입력은 [issue-context.tsv](issue-context.tsv).

| id | 유형 | 프롬프트 | 기대 |
| --- | --- | --- | --- |
| p1 | 양성 | MOI-601 분석해줘 | yes |
| p2 | 양성 | 이 이슈 파악 좀: MOI-602 | yes |
| p3 | 양성 | MOI-603 관련 PRD랑 코드 컨텍스트 정리해줘 | yes |
| p4 | 양성 | MOI-604 가 뭘 해야 하는 이슈인지 요약해줘 | yes |
| p5 | 양성 | 이슈 MOI-605 컨텍스트 수집해서 worklog에 남겨줘 | yes |
| n1 | 음성 | RoomService 변경분 코드 리뷰해줘 | no (리뷰) |
| n2 | 음성 | participation 도메인 구조가 어떻게 돼있는지 설명해줘 | no (코드 질문) |
| n3 | 음성 | 이 레포 테스트 태그 체계 알려줘 | no (컨벤션 질문) |
| n4 | 음성 | git log에서 최근 room 도메인 커밋들 요약해줘 | no (git 조회) |
| n5 | 음성 | worklog README에 있는 오타 고쳐줘 | no (단순 편집) |
| b1 | 경계 | MOI-606 구현해줘 | boundary (req-impl 경유 호출이 정상) |
| b2 | 경계 | MOI-607 이슈 봐주고, 판단 어려운 건 나한테 물어봐 | boundary (분석+질문 유도) |

> n4는 원래 "하네스 커밋 요약"이었으나 1차 실행(2026-08-21)에서 교체했다:
> 과제 자체가 하네스 파일을 읽게 만들어 경로 기반 감지와 충돌한다(codex
> 측정 무효 1건). 음성 프롬프트는 하네스와 무관한 소재로 만든다.
