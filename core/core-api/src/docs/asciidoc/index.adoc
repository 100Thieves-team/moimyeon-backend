== Error Responses (공통 에러 규약)

모든 에러 응답은 같은 봉투를 사용한다. FE 분기는 HTTP 상태 코드가 아니라 `error.code` 를 기준으로 한다.

[source,json]
----
{
  "result": "ERROR",
  "data": null,
  "error": {
    "code": "E1007",
    "message": "이미 사용 중인 닉네임입니다.",
    "data": null
  }
}
----

* `error.code` : 분기 기준이 되는 에러 코드
* `error.message` : 사용자에게 그대로 표시 가능한 한국어 메시지
* `error.data` : 추가 정보. `E400` 중 파라미터 누락·타입 불일치는 파라미터별 사유 맵(`{"query": "required parameter is missing"}`), 그 외에는 `null`

각 API 가 응답하는 예외 케이스는 해당 API 섹션의 Error Responses 표에 정의한다(OpenAPI 스펙의 4xx 응답과 동일).

이와 별개로 모든 API 는 공통으로 아래 두 가지를 응답할 수 있다.

|===
| HTTP | error.code | 케이스

| 400 | E400 | 요청 형식 오류. 요청 DTO 값 규칙 위반·필수 파라미터 누락·타입 불일치·본문 해석 실패(깨진 JSON 등). 파라미터 누락·타입 불일치일 때만 `error.data` 에 사유 맵이 실린다
| 500 | E500 | 서버 내부 오류
|===

인증이 필요한 API 는 액세스 토큰이 없거나 만료·무효이면 `401(E1102)` 로 응답한다.
FE 는 <<_refresh_access_token,재발급 API>> 호출 후 재시도한다. (권한 부족 시 `403(E1103)` 은 인가 정책 확정 후 적용 예정)

== Auth API

=== Google OAuth2 로그인 (수기 문서)

[NOTE]
====
로그인 시작·콜백 엔드포인트는 컨트롤러가 아니라 Spring Security 필터 체인이 처리하므로
REST Docs 스니펫이 아닌 수기로 문서화한다. 동작은 성공·실패 핸들러 단위 테스트와 실제 필터 체인
컨텍스트 테스트로 검증하며, 같은 두 경로와 302 응답 계약은 생성된 OpenAPI에도 포함된다.
====

로그인 플로우:

1. 프론트엔드가 브라우저를 `GET /oauth2/authorization/google` 로 보낸다 (fetch/XHR 이 아닌 전체 페이지 이동).
2. 서버가 구글 동의 화면으로 `302` 리다이렉트한다.
3. 사용자가 동의하면 구글이 `GET /login/oauth2/code/google?code=...` 콜백으로 리다이렉트한다.
4. 서버가 회원을 조회/등록하고 세션을 연 뒤, 다음 두 쿠키를 `Set-Cookie` 로 내려준다:
** `ACCESS_TOKEN` — JWT 액세스 토큰. `Path=/`, `HttpOnly`
** `REFRESH_TOKEN` — 세션 리프레시 크리덴셜. `Path=/v1/auth`, `HttpOnly`
5. 두 쿠키가 모두 준비된 뒤에만 `Set-Cookie` 헤더를 기록하고, 설정된 프론트 성공 콜백
   (`https://moimyeon.plady.io/auth/callback`)으로 `302` 리다이렉트한다.

실패 플로우:

* 사용자가 Google 동의를 거절하거나 Google이 오류를 반환한 경우
* OAuth `state`가 없거나 일치하지 않는 등 콜백 검증에 실패한 경우
* Google 인증 뒤 회원 조회·가입, JWT 발급, 세션 저장, 쿠키 생성 중 하나라도 실패한 경우

위 실패는 모두 새 인증 쿠키를 발급하지 않고 설정된 프론트 실패 URL
(`https://moimyeon.plady.io/?authError=login_failed`)로 `302` 리다이렉트한다. 공급자 오류 설명이나 내부 예외
메시지는 URL과 응답에 노출하지 않는다. 회원 확정과 세션 저장은 별도 트랜잭션이므로 회원 확정 뒤 세션
발급이 실패할 수 있으며, 이 경우 다음 로그인은 이미 확정된 회원을 재사용해 복구한다.

성공·실패 리다이렉트 URI는 각각 `OAUTH_FRONTEND_SUCCESS_REDIRECT_URI`,
`OAUTH_FRONTEND_FAILURE_REDIRECT_URI` 환경변수로 바꿀 수 있다. `local` 기본값은 `localhost:3000`,
그 외 프로파일 기본값은 `moimyeon.plady.io`다.

이후 API 인증은 `ACCESS_TOKEN` 쿠키(웹) 또는 `Authorization: Bearer {token}` 헤더(앱) 둘 다 허용한다.
액세스 토큰이 만료되면 아래 <<_refresh_access_token,재발급 API>> 를 호출한다.

== Resume API

이력서는 인증 회원이 소유하는 비공개 자원이다. 마이페이지의 보관함뿐 아니라 룸 생성·참가 신청에서도
같은 `resumeId`와 응답 형태를 재사용한다. 원본과 보관 목록은 본인에게만 노출하며, 룸에서의 공개는
별도의 제출 기록과 해당 룸의 공개 정책을 따른다.

룸 생성·참가 신청 화면에서 새 파일을 올려도 `POST /v1/members/me/resumes`로 회원의 보관함에 먼저
등록하고, 응답의 `resumeId`를 해당 요청에서 선택한 이력서로 사용한다. 신청은 AI 요약 완료를 기다리지
않으며, 등록된 이력서는 이후 마이페이지와 다른 신청에서도 다시 선택할 수 있다.

최신 「회원 및 프로필」 PRD 기준 최대 보관 개수는 10개다. 등록한 이력서는 수정하지 않고 새 이력서를
등록하며, 삭제한 이력서는 이후 선택 목록에서 제외하되 이미 제출한 룸의 기록에는 영향을 주지 않는다.
목 API는 `local`·`local-dev`·`dev`에서만 활성화되며 고정 예시를 반환한다.

=== 보관 이력서 단건 조회

== Room (룸·면접) API

모의면접 룸의 생성·탐색·참가 신청 관리를 위한 API. 데이터·코드에서는 룸(Room), 사용자 화면 표기는 면접이다.
회사·직무·지역은 <<_catalog_api,Catalog API>> 를 참조 id 로 연결한다. 회사는 공고를 고르면 함께 확정되므로 룸에는 따로 저장하지 않는다.
룸 id 는 외부 노출 식별자라 UUID(UUIDv7 계열)다.
