# MOI-541 컨텍스트

Linear: https://linear.app/100-thieves/issue/MOI-541/mvp-룸-자동-완료-및-완료-후-출석-분리

MVP 룸 상태는 `RECRUITING → CONFIRMED → COMPLETED`이며 `IN_PROGRESS`는 제거한다.
방장은 별도 취소 버튼 대신 룸에서 나간다. 후임이 있으면 위임하고, 확정 룸이었다면 `RECRUITING`으로 돌아간다.
후임이 없을 때만 `CANCELED`로 닫는다.

## 확정 요구사항

- 방장 이탈 + 후임 있음: 방장 위임. 모집 중이면 그대로, 확정이면 모집 중으로 복귀한다.
- 확정 후 모집 중으로 복귀한 룸은 일정이 지난 뒤라도 새 방장이 재확정해 완료할 수 있다.
- 방장 이탈 + 후임 없음: `CANCELED`로 전환하고 남은 신청을 시스템 종료한다.
- 명시적 완료: 방장이 `POST /v1/rooms/{roomId}/complete`를 호출하면 즉시 완료한다.
- 자동 완료: `startAt + 8시간 <= now`인 `CONFIRMED` 룸을 worker가 완료한다.
- 출석: 완료 전이와 분리해 완료 후 방장이 확정 참여자 전원의 참석 여부를 한 번 기록한다.
- 알림: 확정·완료·취소는 전체 대상자에게, 리뷰 요청은 출석 저장 후 참석자에게 보낸다.
- 진행 레일·진행 중 질문/댓글·라운드 피드백 HTTP API는 MVP 공개 계약에서 제외한다.
- 배포 전 변경이므로 레거시 `IN_PROGRESS` 데이터 호환은 하지 않는다.

## 데이터 영향

확정 후 모집 중 복귀와 재확정이 가능하므로 `room_status_log`에는 같은 전이 종류가 반복된다.
확정 참여자 판정은 가장 최근의 활성 `CONFIRMED` 로그 시점만 기준으로 삼는다.
`COMPLETED`와 `CANCELED`는 생성 컬럼 기반 유니크 제약으로 룸당 하나의 terminal 전이만 허용한다.
