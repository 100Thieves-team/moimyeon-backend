# MOI-541 결정 기록

## DR-001 IN_PROGRESS를 제거한다

- 상태 enum과 전이에서 `IN_PROGRESS`를 제거한다.
- 신규·레거시 호환 경로를 나누지 않는다. 아직 배포 전이므로 데이터 이관 대상이 없다.

## DR-002 방장 이탈이 취소와 위임을 결정한다

- 명시적 룸 취소 HTTP API는 제거한다.
- 방장 이탈 시 후임이 있으면 위임한다.
- 확정 상태에서 위임되면 참여 구성이 바뀌므로 모집 중으로 돌아가 재확정한다.
- 이전 확정 이력이 있는 룸은 일정이 지났어도 새 방장이 재확정할 수 있어 활성 룸이 고립되지 않는다.
- 후임이 없을 때만 취소한다.

## DR-003 완료와 출석을 분리한다

- 완료는 방장 수동 액션 또는 예정 시각 8시간 뒤 worker가 수행한다.
- 완료 전이에는 출석을 요구하지 않는다.
- 출석은 완료 후 방장이 최신 확정 참여자 전체를 대상으로 한 번 기록한다.
- 리뷰 요청은 출석 저장 뒤 참석자가 둘 이상일 때 참석자에게 발행한다.

## DR-004 반복 상태 이력을 허용한다

- `RECRUITING`과 `CONFIRMED`는 반복 기록하고 append-only 이력으로 유지한다.
- `COMPLETED`와 `CANCELED`는 룸당 하나만 기록되도록 terminal 전이 유니크 제약을 유지한다.
- 확정 명단 조회는 가장 최근 `CONFIRMED` 로그만 사용한다.

## DR-005 알림 소비자 호환 버전을 먼저 배포한다

- 새 `EventType`을 이해하는 worker를 먼저 배포한 뒤 생산 기능을 배포한다.
- 자동 완료는 상태·SYSTEM 로그·수신자별 Outbox를 같은 트랜잭션으로 저장한다.
- worker는 한 실행에 오래된 룸을 최대 100건 처리해 backlog가 메모리를 무제한 점유하지 않게 한다.
