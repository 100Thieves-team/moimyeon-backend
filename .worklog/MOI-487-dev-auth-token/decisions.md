# 구현 결정

## 운영 발급과 개발용 무기한 발급을 메서드 수준에서 분리
- 날짜: 2026-08-27
- 내용과 이유: 기존 `issue`는 항상 30분 만료를 보장하고, 개발 전용 호출만 명시적인 `issueWithoutExpiration`을 사용한다. nullable TTL 같은 범용 옵션으로 만들면 운영 호출이 실수로 만료를 생략할 수 있어 두 의도를 공개 메서드 이름으로 분리한다.
- 대안: `issue`에 nullable 만료 시각이나 플래그를 받는 방식. 호출부에서 보안 정책이 드러나지 않고 잘못된 조합을 허용해 제외한다.

## 개발 로그인은 액세스 토큰만 반환하는 무상태 흐름으로 전환
- 날짜: 2026-08-27
- 내용과 이유: 승인된 요구사항대로 리프레시 세션 저장과 두 쿠키 생성을 제거하고 액세스 토큰 문자열만 반환한다. 개발자가 응답을 환경 변수와 Bearer 헤더에 바로 쓰는 목적에 불필요한 서버·클라이언트 상태를 남기지 않는다.
- 대안: 기존 쿠키와 새 응답 토큰을 함께 발급하는 호환 방식. 완전 전환 결정과 어긋나고 사용 경로가 둘로 남아 제외한다.

## 운영성 프로파일이 섞이면 개발 인증 빈을 닫는다
- 날짜: 2026-08-27
- 내용과 이유: 개발 프로파일과 staging·live가 동시에 활성화된 오설정에서도 무기한 토큰 엔드포인트가 등록되지 않도록 `!staging & !live`를 명시한다. 인증 없는 무기한 토큰 발급은 혼합 프로파일에서 fail-closed여야 한다.
- 대안: `!live`만 유지하고 배포 설정이 프로파일을 섞지 않는다고 가정하는 방식. staging 노출을 코드가 막지 못해 제외한다.
