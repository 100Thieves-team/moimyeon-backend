# MOI-411 확정 정책과 남은 작업

2026-09-14. 사용자가 추천안을 채택하고 live 담당자를 팀원 3명 전원으로 지정했다. [설계안](design.md)과 [DR-22](decisions.md)의 정책을 따른다.

2026-09-18에는 구현 세부 정책 7가지와 라이브러리·의존성·Bean 구성도 승인받았다. [DR-26](decisions.md)에 해당 범위와 영향을 기록했으며 사용자 미결정 항목으로 다시 다루지 않는다.

## 확정한 정책

| 항목 | 확정 내용 |
| --- | --- |
| 보존 | CloudWatch debug 3일만, ops 7일과 S3 ops/growth 90일 |
| 로그 유실 | 일반 운영 로그는 서비스 가용성 우선. 버퍼 포화·호스트 장애 때 유실 허용 |
| WARN | environment/service/eventKey별 고정 60초 Sum >= 5 |
| ERROR | 첫 발생·해결 후 재발 즉시. 같은 오류가 계속 발생하면 최소 10분 간격으로 묶어 알림 |
| 일일 보고 | 09:00 KST, 전날 WARN 요약 |
| slow 시작값 | 일반 API 1초. 업로드·LLM은 별도 기준 |
| 담당·채널 분리 | live는 팀원 3명 전원이 공동 담당·수신. dev/staging과 live 채널 분리 |
| 감사 대상 확인 | 실제 관리자 개인정보 열람·다운로드·권한 변경부터 확인 |

## 연결·운영 단계에서 확인할 것

| 항목 | 남은 내용 |
| --- | --- |
| 실제 알림 목적지 | live/dev 채널 식별자와 팀원 3명의 수신 계정. 이름·계정을 추정하지 않음 |
| critical 대응 | 반복·상향 통지 규칙과 야간 응답 SLA. 전원 공동 담당을 24시간 응답 의무로 해석하지 않음 |
| 실제 감사 대상 | 현재 관리자 기능 확인, 필수 기록·보존·내구성·저장 실패 시 작업 거부 여부 |
| SID·UTM | 그로스 구현 전에 FE 전달·쿠키 범위·수명·최초/최근 유입·키 회전 정책 확인 |
| 파생 자료 보존 | Sentry·reports·알림 채널·CI 산출물의 복제본 정책. 일반 로그 보존과 별도 확인 |

## 구현·측정으로 정할 것

| 항목 | 검증 내용 |
| --- | --- |
| WARN 수준 이관 | 정상 업무 거절 INFO·기능 저하 WARN 분류, HTTP 계약 유지, 중복 진단 방지 |
| 알림 정확성 | 고정창 4/5회·분 경계·다중 task·수신 중복, Sentry 최초/재발/지속 규칙과 실제 플랜 지원 |
| 일일 보고 | query 실패·실행 누락·지연 로그·중복 통지를 0건 또는 정상으로 오인하지 않음 |
| DEBUG 보존 | S3·Sentry breadcrumb 유입 차단, 원래 timestamp, filesystem buffer 분리와 실제 만료 |
| 버퍼·router 자원 | dev API 2vCPU/1600MiB 예약을 고려해 배포 용량·cold start·p99·손실량 측정 후 자원 배분 또는 Firehose 비교 |
| 전달 지연 | canary 도착·가장 오래된 미전송 시간·포화 부하 관측. best effort를 무손실로 표현하지 않음 |
| slow 조정 | 일반 API 1초를 기준으로 메트릭 분포 확인, 업로드·LLM별 응답 예산 설정 |
| 환경 부팅 | 환경별 Logback XML 선택·상충 환경 거부·test/local 상속 예외·초기화 전 원문 차단 |
| Sentry 연결 | 안전한 eventCode/errorCode/requestId/traceId/spanId 보존, 원본 context 전체 복사 금지 |
| IAM | task role 공유를 명시하고 로그 Get/Delete 권한 제외. 실제 최소 권한 확인 |

공통 로깅 설정과 요청 요약 작성기는 구현·검증했고 미커밋 상태다. HTTP 필터 연결·인프라 배포·외부 통지는 아직 수행하지 않았다.
