# MOI-540 미결정 사항

이슈가 "정의되지 않은 정책·스펙을 먼저 정의"를 요구하므로, 아래 항목은 구현 전에
결정하고 wiki-sync로 PRD(`raw/product/회원-및-프로필` §4.8)와 상태 SSOT에 반영해야 한다.

정해진 항목은 [decisions.md](decisions.md)로 옮겼다 (A 전체, B-3·4, C-6, D-11 문구 통일 여부).

## A. 이번 PR 범위 — 해결: MOI-562로 분리

1. **7일·30일 후속 처리를 이번 PR에 넣을지.** 이력서 삭제(`C.resume.purge`, 7일)와
   개인정보 마스킹(`C.member.mask_pii`, 30일)은 정기 작업이 필요하다. 실행 방식도 미결이다 (D24).
   선택지: 탈퇴 API만 이번에 / 정기 작업까지 이번에 / 탈퇴 시점에 즉시 처리해 정기 작업을 없앤다.
2. **S3 이력서 파일 삭제.** `S3ResumeFileStore`에 삭제 기능이 없다. 7일 삭제를 지키려면 추가해야 한다.

## B. 활성 룸 처리 (PRD R95–R97) — 3·4 해결: MOI-561

3. **확정 룸의 일반 참여자.** `RoomLeaveManager`는 최소 인원 이하가 되면 나가기를 막는다
   (`ROOM_AT_MIN_CAPACITY`). PRD는 즉시 탈퇴를 허용하므로 탈퇴 경로에서는 이 검사를 건너뛸지,
   아니면 룸을 어떻게 둘지 정해야 한다.
4. **"진행 중 룸은 노쇼 처리"(R97).** MOI-541로 `IN_PROGRESS`가 없어졌다. 확정 룸에서 탈퇴한
   참여자를 나간 사람으로 둘지 불참으로 기록할지 정해야 한다 (D23과 연결).
5. **완료된 룸의 후기 작성 기간 중 탈퇴.** 후기 대상 목록에서 빠지는지, 이미 쓴 후기는 그대로인지.

## C. 인증·세션

6. ~~**세션 정리.**~~ 해결: 전부 폐기. 회원의 리프레시 토큰 전체를 폐기할지(현재 회원 단위 폐기 메서드 없음).
   리프레시는 이미 막히지만 액세스 토큰(30분)은 남는다. 인증 필터와 `LoginMemberArgumentResolver`는
   요청마다 회원 존재를 확인하지 않는다. 남은 최대 30분을 허용할지 정한다.
7. **재가입.** 방향 결정: 회원 행이 남아 있으면 복구, 없으면 새 가입. 남은 것: 복구 범위, 자동 복구 여부. 코드는 같은 Google 계정의 재가입을 영구히 막는다(`MEMBER_ALREADY_WITHDRAWN`).
   PRD는 말하지 않는다 (`G.member.signup` 열린 질문). 30일 마스킹 뒤에도 막을지 정해야 한다.
   `social_account.provider_id`를 마스킹하면 재가입 차단도 함께 풀리므로 마스킹 범위와 같이 정한다.

## D. 데이터 처리 기준

8. **탈퇴 상태 표현.** SSOT는 `account_status = WITHDRAWN`, 코드는 `deleted_at`(storage.md 규칙).
   코드가 기준이므로 SSOT 표기를 코드에 맞춰 고칠지 정한다.
9. **마스킹 대상.** 관심 직무가 목록에 없다 (`F.member.job` 열린 질문). 닉네임을 마스킹한 뒤
   유니크 제약을 계속 차지할지 (`F.member.nickname` 열린 질문).
10. **이력서 삭제 방식.** 소프트/하드, 7일 기산점(탈퇴 요청 시각) (`F.resume.purged_at`).
11. **탈퇴 작성자 표시 문구.** 통일하기로 함. 추천: "탈퇴한 회원" (확인 중). PRD는 "탈퇴한 사용자", DEC-005는 "탈퇴한 회원", 코드에는
    "탈퇴한 회원"과 "탈퇴 회원"이 섞여 있다. 하나로 정한다.
12. **D39 해소.** 후기·신뢰 통계·제출 이력서 기록을 탈퇴 후 어떻게 다룰지 근거를 PRD에 남긴다.

## E. API 계약

13. URI와 메서드: `DELETE /v1/members/me` 또는 `POST /v1/members/me/withdraw` (api-design.md 기준 확인).
14. 탈퇴 사유 수집 여부 (PRD에 없음).

## F. MOI-561 wiki-sync 중 발견한 탈퇴 쪽 SSOT 낡은 기록 (MOI-540 wiki-sync에서 고친다)

- `X.withdraw.leave_active_rooms` note·detail: "승계 규칙이 없다 / 부를 전이가 없다"는 R31~R36 이후 틀렸다.
  확정 룸 참여자의 탈퇴가 새 전파 `X.participation.reopen_below_min`(MOI-561)을 타는지 명시한다.
- `P.member.withdrawal` open_question: "방장 승계 규칙도 어느 PRD 에도 없어"가 틀렸다.
- `P.participation.exit`: 방장은 떠날 수 없다는 서술이 DEC-010·R31~R36과 어긋난다.
- `공통.yaml` cascades 주석 "전파 다섯 개뿐이다"가 실제 수와 다르다.
