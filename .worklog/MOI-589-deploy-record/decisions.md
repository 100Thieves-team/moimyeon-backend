# MOI-589 결정 기록

## D-1: 기록은 지금처럼 커밋당 하나로 둔다

- 이슈의 [결정 필요] "커밋 단위 기록 하나 / 서비스별 + 커밋 단위"에 대한 답: 커밋 단위 하나.
- 이유: live 승격(promote-live)과 롤백(rollback-aws)이 이 기록 하나를 읽고, 롤백은 이미 API만·Worker만·둘 다를 고를 수 있다.
  교체하지 않은 서비스는 실행 중인 이미지·태스크 정의를 그 커밋 기록에 이어 적으면 기록 하나로 "그 시점에 실제로 돌던 상태"를 가리킨다.
  서비스별 기록을 더하면 승격·롤백·표식(ECR marker) 검증을 모두 바꿔야 한다.

## D-2: 같은 커밋 재배포는 기록된 태스크 정의를 다시 쓴다

- 배포 시작 시 그 커밋의 기록이 있으면(`find-deployment-bundle.sh`) API·Worker 태스크 정의를 새로 등록하지 않고 기록된 revision으로 배포한다.
  기록 단계는 같은 내용이라 "이미 기록됨"으로 통과한다.
- "기록 없음"은 SSM `ParameterNotFound`일 때만이다. 다른 조회 오류는 배포를 멈춘다(새로 등록하면 기록과 충돌하므로).
- 기록에 Worker가 없는데 지금 Worker가 켜져 있으면 멈춘다. 불변 기록을 바꿀 수 없으니 새 커밋으로 배포한다.
- 재배포 사이에 Terraform이 태스크 정의 원본 틀을 바꿨다면 그 변경은 이 커밋에 반영되지 않는다. 새 커밋이 반영한다(기록 불변 우선).

## D-3: 일부만 성공한 배포는 기록하지 않는다

- API 교체 성공 뒤 Worker 이미지 빌드·교체가 실패하면 지금처럼 기록을 남기지 않는다. 롤백 대상은 직전 기록(두 서비스 모두 정확)이고,
  live 승격은 이 커밋의 기록을 찾지 못해 멈춘다(실패 시 멈춤). 실패한 상태를 기록해 live로 승격되는 경로를 만들지 않는다.

## D-4: 기록과 지금 설정이 어긋나면 바꾸기 전에 멈춘다

- 기록에 Worker가 없는데 지금 켜져 있거나, 기록에 Worker가 있는데 지금 꺼져 있으면 기록 찾기 단계에서 멈춘다(qa-reviewer 권고).
- 기록된 태스크 정의의 컨테이너 이미지가 이번 실행의 이미지 태그와 다르면(저장소·컨테이너 이름 변경 등) 서비스를 바꾸기 전에 멈춘다.

## D-5: 교체하지 않은 서비스를 이어 적는 도구는 MOI-590에서 만든다

- 실행 중인 서비스를 읽는 스크립트를 이 PR에 먼저 넣었다가 뺐다. dev 태스크 정의는 digest가 아니라 커밋 태그를 쓰는데
  가짜 digest 입력으로만 시험해 실제 dev Worker에서는 항상 거부되는 것을 리뷰가 잡았다. 실제로 연결하는 MOI-590에서
  태그를 digest로 바꾸는 처리와 실제 형태의 테스트와 함께 만든다.
- 이어 적을 때는 그 이미지에도 이 커밋의 `deployed-dev-<sha12>` 표식을 붙여야 승격·롤백의 표식 검증을 통과한다.
