# 변경 설명 자료

- [x] [전체 계획](../MOI-549-pr-scope/plan.md)의 설명 자료 단계 승인.

change-brief 스킬로 배경·실제 시퀀스·전후 결과·검증과 제한을 작성하고 ship-pr에
인계한다. Claude Artifact 우선이지만 다른 공유 문서도 허용한다는 사용자 확인을
적용한다. 하네스 문서는 GitHub Markdown으로 공유하며 Wiki를 만들지 않는다.

게시 수단별 절차는 reference로 분리한다. GitHub 원문은 push 뒤 permalink를
PR에만 적으며, PR 이후 worklog 동결과 충돌하지 않도록 변경된 설명은 PR 본문의
최신 설명 또는 외부 공유 문서에 반영한다.

검증 계획: 신규 스킬 lint·메타데이터, 네이티브 독립 세션의 호출 경계, 공유 도구
부재 시 대체 문서, 로컬 파일만 생성한 상태의 미완료 판정, PR 뒤 설명 갱신 경로를
검토한다. 원문과 링크·렌더링 확인을 구분한다.

## 검증 결과

스킬 lint와 quick_validate를 통과했다. 네이티브 독립 세션(N=1/입력, 주 세션 모델
상속, 세부 런타임 버전 미노출)에서 설명 자료 요청 2개는 change-brief,
제품 명세 대조는 wiki-sync, 설명 자료가 필요 없는 회귀 위험 리뷰는 qa-reviewer를 선택했다. 공유 설명의 실패 분기 수정은 change-brief를 선택했다.
5개 가상 상황의 독립 평가에서는 GitHub Markdown 대체, 로컬 파일만으로 게시 완료
불가, PR 뒤 worklog 동결과 최신 PR 본문 설명, 필수 명세 갱신 이연 금지, 게시 수단이
없을 때 원문 준비 후 마지막 단계 인계를 확인했다. 실제 주소·렌더링은 push 후 확인한다.
외부 Claude CLI 평가는 자동 승인 검토의 데이터 전송 거절을 따라 재시도하지 않았다.

읽기 전용 리뷰에서 ship-pr 내부의 정상 호출과 충돌하는 음성 입력을 발견해 설명 자료가 필요 없는 QA 리뷰 요청으로 바꾸고 새 세션에서 재측정했다. 수정 후 정적 재검토는 PASS다.
