# MOI-563 컨벤션 polishing 설명

## 배경

리뷰에서 같은 지적이 반복됐다.

- `xxxService`, `xxxManager`를 담는 필드·변수를 `service`, `manager`로 짓는다. 한 클래스에 의존이 여럿이면
  어느 컴포넌트인지 이름만으로 알 수 없고, 테스트에서는 대상과 mock이 섞여 읽힌다.
- 컨벤션 문서로 이미 알 수 있는 사실("Service 는 판정하지 않는다", "응답 조립은 Facade 가 한다")을
  클래스마다 주석으로 다시 적는다. 같은 이유가 여러 파일에 복사되면 하나만 고쳐져 서로 어긋난다.

두 규칙이 문서에 없어서 매번 사람이 지적해야 했다. 이번 작업은 규칙을 문서로 굳히고 기존 코드를 맞춘다.

## 바뀐 규칙

`docs/conventions/kotlin-style.md`

- **컴포넌트 이름**: 이 레포의 컴포넌트를 담는 프로퍼티·변수는 역할 단어 하나로 짓지 않는다.
  기본은 타입명 camelCase, 같은 클래스 안에서 뜻이 분명하면 줄여도 된다(`accessValidator`). 테스트도 같다.
  라이브러리 객체와 값(enum 상수, 데이터 클래스 필드)은 대상이 아니다.
- **주석 금지 항목 추가**: 컨벤션 문서로 알 수 있는 사실, 같은 이유의 여러 파일 반복, RestDocs와 겹치는 DTO 주석.
  컨벤션이 주석을 요구하는 경우(Repository로 직접 내려간 이유, 베이스를 상속하지 않는 엔티티의 이유)는 예외다.

README 한 장 요약과 `code-reviewer` 점검 항목에도 같은 규칙을 넣어 리뷰 단계에서 걸리게 했다.

## 코드 정렬 결과

| 구분 | 변경 | 동작 영향 |
| --- | --- | --- |
| 이름 | 약 135곳. 대부분 테스트 대상·mock, main은 6개 파일 | 없음. 생성자 주입은 타입으로 해석되고 named argument를 쓰는 호출부도 함께 바꿈 |
| 주석 | main 코드 약 100개 파일 | 없음. 주석 외 코드 변경 없음 |

주석에서 지운 것은 엔드포인트 경로·동작을 다시 적은 주석, 레이어 역할 설명, DTO 필드 값 예시, 메서드 이름을 풀어 쓴 Repository 주석, 변경 이력이다.
코드로 안 보이는 이유, 계약 선언, TODO, 컨벤션이 요구하는 주석은 남겼다. 여러 곳에 있던 이유는 규칙이 걸리는 한 곳으로 모았다
(예: 방장 판정 소유 설명을 두 Manager에서 `ParticipationValidator.validateHost` 한 곳으로).

## 검증

- `./gradlew test ktlintCheck` 통과(분할한 각 PR 브랜치에서도 실행)
- 이름 변경이 없는 파일은 주석을 걷어낸 뒤 변경 전과 같은지 스크립트로 대조

## 제한

- 줄임 이름(`accessValidator` 등)은 규칙상 허용이라 그대로 두었다.
- 정리 중 위치가 잘못 붙은 CONFIRMED 조건 주석은 해당 쿼리 위로 옮겼다. 그 밖에 내용이 틀렸을 수 있는 주석과 컨벤션이 요구하는데 빠진 주석을 발견했지만, 새 주석을 쓰거나 사실을 확인하는 일은 범위 밖이라 PR 본문 후속 작업에 남겼다.
