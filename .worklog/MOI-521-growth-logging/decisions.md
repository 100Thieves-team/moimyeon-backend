## 구현 결정 (4단계, 로깅 계약)

| # | 결정 | 이유 |
| --- | --- | --- |
| I1 | Writer는 고정 표식 message(`growth.event`)와 payload로 엔트리를 넘기고, Sanitizer가 표식과 타입이 모두 맞을 때만 그로스로 출력한다. 출력 `message`는 사건명으로 바꾼다 | `RequestLogEntry` 선례. 사건명만 흉내 낸 일반 로그가 그로스로 승격되지 않는다 |
| I2 | 별도 `occurredAt` 없이 공통 `timestamp`를 사건 시각으로 쓴다 | 커밋 직후 기록하므로 차이가 작고 필드를 늘리지 않는다 |
| I3 | 사건명은 정확히 두 마디, 속성 값은 Int·Long·Boolean·UUID·enum만(문자열 불가, 리뷰 반영) | 문자열은 형태 검사로 닉네임·전화번호를 거를 수 없다. 분류 값은 enum으로 넘긴다. 숫자에 개인 식별 값을 넣지 않는 것은 5단계 호출 지점 리뷰 항목 |
| I4 | dev 구분은 새 필드 없이 공통 `environment`를 쓴다(D17) | 이미 모든 줄에 있다 |
| I5 | 엔트리는 data class가 아니고 속성 map을 복사해 보관한다. 표식 없이 payload에 들어온 엔트리는 일반 로그에서 버린다(리뷰 반영) | 생성 후 원본 map 변경으로 검증을 우회하거나, 자동 toString으로 analyticsId가 일반 로그에 나가는 것을 막는다 |
| I6 | 속성 키는 `[A-Za-z][A-Za-z0-9_]*`로 기존 필드명 문법보다 좁힌다 | PostHog 속성 이름과 그대로 맞춘다 |
| I7 | 그로스 출력은 표식·타입·INFO 수준이 모두 맞을 때만 한다(QA 참고 3 반영) | 다른 수준으로 남긴 엔트리가 운영 로그 경로에 가명 ID를 남기지 않게 한다 |
