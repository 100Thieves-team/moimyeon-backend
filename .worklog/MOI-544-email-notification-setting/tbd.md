# MOI-544 미결정 사항

미결정 사항 없음.

## 결정됨

### 설정 항목 (2026-10-01 ~ 10-02)

- 설정 항목은 3개: 서비스 활동 알림(웹 푸시) / 서비스 활동 알림(메일) / 광고성 정보 수신. 이벤트 종류별로 나누지 않는다.
- 필수 안내(약관 변경 등)는 설정과 무관하게 항상 보낸다. 지금 코드에는 이런 메일이 없다.
- 기본값: 서비스 활동 알림 2개는 신규·기존 회원 모두 켜짐. 광고성 정보는 꺼짐(사전 동의).
- 변경 이력은 남기지 않는다. 현재값만 저장한다. 단, 광고성 정보는 마지막 동의 시각을 함께 저장한다.

### 광고성 정보 (2026-10-02)

- 메일로만 보낸다(푸시 광고 없음 → 야간 발송 동의 불필요).
- 가입 때 받지 않고 설정에서만 켠다.
- 동의·철회 처리 결과는 화면으로 알린다.
- 2년마다 재확인은 이번 범위에서 뺀다.
- 서비스 활동 알림의 정책 체계에 넣지 않는다. 이번에는 동의 여부와 마지막 동의 시각 저장만 한다.

### 웹 푸시와 기기 등록 (2026-10-01 ~ 10-02)

- 기존 구독 등록·해지 API를 수신 설정 API로 편입한다. 기존 경로(`/v1/members/me/web-push-subscriptions`)는 바로 없앤다(dev 배포). 프론트와 함께 맞춘다.
- 푸시를 켜면 꺼짐 값을 풀고 이 브라우저의 토큰을 저장한다. 다른 기기에서 켜면 토큰이 하나 더 저장된다.
- 푸시를 끄면 꺼짐 값을 설정하고 그 회원의 모든 기기 등록을 지운다.
- 푸시가 꺼진 동안 들어온 기기 등록 요청은 저장하지 않는다. 서버에서 토큰을 지워도 다른 기기의 브라우저 권한은 남아 토큰이 다시 올 수 있기 때문이다.
- (2026-10-02 변경) 서버는 푸시를 "켜짐" 기본값으로 저장하지 않고 "푸시 거부 여부"(기본: 거부 안 함)만 저장한다. (이후 이름만 긍정형 `is_web_push_allowed` 로 바꿈 — decisions.md "Boolean 이름") 웹 푸시는 브라우저 허용 창이 사실상 동의 절차라 가입 단계 동의가 필요 없다. 설정 화면의 푸시 토글은 이 브라우저 기준(거부 안 함 + 권한 허용 + 이 브라우저 토큰 등록)으로 표시한다. 허용 창을 띄우는 시점은 프론트가 정한다.
- 역할 분담: 서버는 거부 여부를 저장하고 거부 상태의 등록을 막는다(마지막 방어선). 클라이언트는 허용 창 시점, 토큰 등록·`deleteToken()` 시점, 앱을 열 때 서버 설정 조회 후 맞추기를 맡는다.

### 발송 구조 (2026-10-02)

- 이벤트가 정책(채널)을 고르는 기존 방식(`NotificationPolicy` 4종, 이름 유지)을 그대로 둔다.
- 정책은 "무엇을 시도할지"(의도)만 정하고 설정을 보지 않는다. ELSE(푸시가 안 닿으면 메일) 허용 여부는 이벤트마다 다른 제품 판단이므로 정책에 남긴다.
- worker가 보내기 직전에 받는 사람의 설정·기기 유무·전송 결과를 보고 의도를 가능한 만큼 실행한다.
  - 푸시 메시지: 푸시 설정 켜짐 + 기기 있음이면 푸시. 전달 안 됨 + 정책이 ELSE 허용 + 메일 설정 켜짐이면 메일.
  - 메일 메시지: 메일 설정 켜짐이면 메일.
- 푸시 꺼짐은 기기 삭제의 부수 효과가 아니라 설정값으로 직접 판단한다. 기기 삭제는 토큰 정리 역할이다.
- 결과: 푸시 꺼짐 + 메일 켜짐이면 PUSH_ELSE_EMAIL 알림은 메일로 간다. 둘 다 꺼지면 방 취소·확정 알림도 보내지 않는다(이벤트별 예외 없음). 둘 다 끌 때 경고하는 것은 프론트 몫.
- 설정을 끈 직후 대기 중이던 알림도 보내기 직전 설정을 따르므로 나가지 않는다. 그대로 둔다.

### 엔티티 설계 (2026-10-02)

- 끄기와 토큰 갱신이 동시에 들어와 끈 뒤에 토큰 한 건이 남는 경우는 따로 막지 않는다. 중요도가 낮다고 판단했다.
- 수신 설정은 `member` 에 컬럼으로 둔다. shared PK 별도 테이블은 V6 에서 member_profile 이 겪은 문제(PRIMARY 충돌 판별 불가·회원 행 락 의존)와 백필 부담 때문에, member_profile 은 공개 소개 정보라 비공개 계정 설정과 성격이 달라서 택하지 않았다.
