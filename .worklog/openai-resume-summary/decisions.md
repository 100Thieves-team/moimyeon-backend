# Bedrock Claude 3.5 Sonnet 전환 결정

## DR-001 서울 In-Region 모델 사용

- 결정: `anthropic.claude-3-5-sonnet-20240620-v1:0` direct model을 사용한다.
- 이유: 서울 In-Region에서 현재 계정 agreement가 활성화된 범용 모델 중
  이력서 요약 품질이 가장 높고, 국외 이전 부담을 만들지 않는다.
- 대가: 최신 Global 모델보다 모델 세대와 성능이 낮을 수 있다.

## DR-002 PDF 원본을 모델에 전달하지 않음

- 결정: 모든 PDF에서 서버가 텍스트를 추출하고, 검증·마스킹한 텍스트만
  Bedrock에 전달한다.
- 이유: PDF에 포함된 직접 식별정보의 모델 전달을 최소화한다.
- 제외: OCR과 raw PDF fallback.

## DR-003 최소 무결성 검사

- 결정: 위치 기준 추출, NFC 정규화, 빈 결과·명백한 Unicode 손상·암호화·
  손상 PDF 거부까지만 결정적으로 검사한다.
- 이유: 표·2열 문서에서 텍스트 순서가 달라져도 LLM이 문맥으로 해석할 수
  있으며 두 추출 방식 일치 강제는 정상 이력서를 과도하게 거부한다.
- 잔여 위험: 정상 Unicode로 잘못 매핑된 glyph와 표의 의미 연결 오류는
  OCR 없이 판정할 수 없다.

## DR-004 개인정보 마스킹 범위

- 결정: 이메일, 한국 유·무선 전화번호, 주민등록번호는 패턴으로 마스킹하고
  주소는 라벨 줄과 대표적인 비라벨 도로명 패턴을, 학번은 라벨 줄만 마스킹한다.
- 잔여 위험: 비정형 주소·비라벨 학번과 문맥형 개인정보는 탐지하지 못한다.

## DR-005 Bedrock IAM 최소 권한

- 결정: ECS task role은 현재 AWS 리전의 Claude 3.5 Sonnet foundation model
  ARN 하나에만 `bedrock:InvokeModel`을 허용한다.
- 이유: Global inference profile 권한을 제거해 국외 라우팅을 기술적으로
  허용하지 않는다.

## DR-006 출력 규칙 결정적 검증

- 결정: 모델 응답은 한국어 1~2문장이고 평가 표현이 없어야 한다. 위반하면
  같은 입력으로 최대 한 번 재생성하고, 다시 위반하면 요약 실패로 처리한다.
- 이유: 프롬프트만으로는 장문 입력에서 평가 표현 금지를 보장하지 못했다.
- 대가: 위반 응답에서 Bedrock 호출 비용과 지연이 최대 한 번 추가된다.

## DR-007 동기 처리 자원·시간 상한

- 결정: PDF는 최대 50페이지·추출 문자열 60,000자로 제한한다. 요청 흐름이
  시작될 때 45초 monotonic deadline을 만들고 S3 저장·조회와 모델 호출에
  공유한다. 모델 호출은 회당 20초로 제한하며 다음 호출을 마칠 여유가 있을
  때만 호출한다.
- 이유: 1분 요약 상태 만료와 ALB 기본 제한 전에 동기 요청을 종료하고,
  압축률이 높거나 페이지·텍스트 객체가 많은 PDF의 자원 사용을 제한한다.
- 대가: 상한을 넘는 장문 포트폴리오는 요약 실패로 처리한다.
