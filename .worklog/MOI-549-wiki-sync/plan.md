# 관련 명세 확인 단계

- [x] [전체 계획](../MOI-549-pr-scope/plan.md)의 Wiki 단계와 사용자 범위 수정 승인.

제품 요구사항·스펙 또는 필요한 ADR만 Wiki를 읽는다. 하네스·컨벤션 등 로컬
문서로 충분한 작업에 Wiki 조회·새 문서·링크를 강제하지 않는다. 필요한 명세
갱신의 후속 이연 금지는 적용 대상 작업에서 유지한다.

공통 조건은 AGENTS.md, 읽기 전용 수집은 issue-context, 실제 원본 갱신·대조는
wiki-sync, 마지막 완료 확인은 ship-pr에 연결한다. 개별 스킬에는 entity-design의
팀 합의 변경 후 재확인만 넣는다. qa-reviewer는 원본 증거와 diff를 함께 비교한다.

새 스킬 발견을 막던 Claude 절대경로 symlink를 상대경로로 고치고, 평가 러너의
과거 이슈 고정 출력 경로를 제거한다. 평가에는 모델·출력 경로를 명시하고
Claude의 도구를 읽기 전용으로 제한해 Wiki·게시·Git 외부 변경을 막는다.

검증 계획: 스킬 lint·frontmatter 검증, 격리 fresh-session 트리거 평가,
제품 명세 모호성/원본 갱신 실패/정합성 불일치/명세 이연 거부/하네스 비대상
시나리오를 읽기 전용 독립 평가로 확인한다. 이번 변경 자체는 Wiki 비대상이다.

## 구현·검증 결과

- 스킬 lint, skill-creator quick_validate, shell 구문, 변경 파일 공백 검사 통과.
- 독립된 네이티브 Codex 세션에서 라우팅을 확인했다(N=1/입력, 모델은 주 세션 상속,
  런타임 세부 버전은 도구에서 제공하지 않음). wiki-sync 양성 2개는 해당 스킬을
  읽었고, 이슈 파악은 issue-context, 하네스 국소 오타는 직접 처리, 관련 ADR 대조는
  wiki-sync를 선택했다. Actions만 변경하는 경계 입력은 infra-change의 actionlint·
  계약 검사와 Terraform 비대상 분기를 선택했다.
- 7개 가상 상황을 신·구 지침에 각각 독립적으로 적용했다. 기존에도 정책 모호점
  질문과 코드 결함 분류는 가능했다. 신 지침은 PRD-SSOT 일부 실패, PR 뒤 명세 누락의
  TODO 이관 충돌, 관련 없는 변경 뒤 대조 근거 재사용을 명시적으로 판정했다.
  하네스 비대상과 필요한 ADR 선택 조회도 확인했다. 실제 Wiki 쓰기를 수행한 평가는 아니다.
- Claude Code 2.1.283/sonnet의 격리 CLI 평가는 인증 오류로 실행되지 않았다.
  권한을 높인 재실행은 저장소 내용을 외부 Claude 서비스로 전송하는 승인이 확인되지
  않았다는 자동 승인 검토의 거절로 중단했다. 우회하지 않고 위 네이티브 새 세션
  평가로 대체했으며 Claude CLI의 성공으로 집계하지 않는다.
- 이 과정에서 인증 실패가 미호출로 집계되는 문제와 인용 문자열의 호출 오탐을
  수정했다. 임시 JSON 픽스처로 인증 실패·빈 출력=ERROR, 단순 인용=no,
  실제 Skill 호출=INVOKED를 확인했다. 결과를 기존 MOI-474 디렉터리에 쓰지 않았다.

읽기 전용 리뷰의 위임 입력 누락과 상대 출력 경로 문제를 수정했다. 관련 Wiki 작업의 리뷰에는 PR 이후 임시 증거와 필요한 원문 발췌까지 전달하며, eval 출력 경로와 worktree 경로는 절대경로로 정규화한다. 모의 CLI로 상대 출력 경로의 5개 raw 파일 생성과 루트 worktree 거부를 확인했다(외부 호출 없음).

최종 통합 리뷰에서 Codex CLI의 read-only 샌드박스가 MCP 외부 쓰기를 막지 않는 점을 확인해 해당 CLI 경로를 차단했다. 네이티브 읽기 전용 독립 평가로 대체하며, 모의 codex 실행 파일이 호출되기 전에 종료 코드 2로 거부되는지 확인했다.
