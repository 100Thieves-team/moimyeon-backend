# 용어 사전

[← 허브로](README.md)

도메인 용어의 **단일 소스**다. 같은 개념을 코드·이슈·PRD·API·테이블에서
다르게 부르면 검색이 끊기고 에이전트가 다른 개념으로 오해한다.

여기 있는 용어는 **코드 식별자·API 필드·테이블 컬럼·이슈 본문에서 같은 말로
쓴다.** 새 개념이 생기면 코드보다 먼저 여기에 한 줄 넣는다.

## 쓰는 법

- **한글 용어**는 사람이 쓰는 말(이슈·PRD·회의), **영문**은 코드 식별자다.
  둘의 대응이 1:1이어야 한다.
- 같은 개념에 별칭이 생기면 별칭을 쓰지 말고 여기의 표준어로 통일한다.
  이미 코드에 별칭이 퍼져 있으면 "표기 흔들림"에 적고 정리 대상으로 둔다.
- 개념 간 **관계·격벽**은 여기가 아니라
  [`concepts.md`](concepts.md)에서 다룬다 — 여기는 낱말의 뜻만.

## 핵심 용어

| 한글 | 영문 | 뜻 |
| --- | --- | --- |
| 모임 | `Room` | 모의 면접이 열리는 단위. 호스트가 만들고 참여자가 들어온다 |
| 호스트 | `HOST` | 모임을 만든 사람. 참여자 역할과 구분된다 |
| 참여자 | `PARTICIPANT` | 모임에 확정 참여한 사람 |
| 참여 신청 | `RoomApplication` | 모임 참여 요청. 수락·거절 판정 대상 |
| 참여 확정 | `RoomConfirmation` | 신청이 수락되어 참여가 확정된 상태 |
| 나가기(참여 취소) | `RoomLeave` | 확정된 참여를 취소하는 행위 |
| 모집 상태 | `RecruitStatus` | 모임의 모집 단계 |
| 정원 | `RoomCapacity` | 모임이 받을 수 있는 인원 |
| 회차 | `Round` | 모임 안에서 진행되는 면접 단위 |
| 진행 | `Progress` | 회차의 실제 수행 상태 |
| 질문 | `Question` | 면접 질문 |
| 답변 요약 | `AnswerSummary` | 답변에 대한 AI 생성 요약 |
| 마무리 | `Closing` | 모임 종료 시점의 절차·응답 |
| 회차 피드백 | `RoundFeedback` | 회차에 대한 상호 피드백 |
| 이력서 | `Resume` | 참여자가 등록한 이력서. 면접 질문 생성의 입력 |
| 회원 | `Member` | 서비스 사용자 계정 |
| 프로필 | `MemberProfile` | 회원의 공개 정보·관심 직군·관심 기업 |
| 직군 | `JobGroup` / `JobRole` | 직무 분류(대분류/세부 역할) |
| 채용 공고 | `JobPosting` | 기업의 채용 공고 |
| 기업 | `Company` | 채용 주체 |
| 출석 | `Attendance` | 회차 참석 여부 기록 |
| 신뢰도 | `Trust` | 참여 이력 기반 사용자 신뢰 지표 |
| 방명록 | `GuestbookPost` | 프로필에 남기는 글 |

## 표기 흔들림 (정리 대상)

같은 개념인데 두 가지로 불리는 것. 발견하면 여기에 적고, 건드리는 김에
표준어로 통일한다.

| 흔들리는 표기 | 표준 | 비고 |
| --- | --- | --- |
| 모임 / 방 / 룸 | **모임**(`Room`) | 코드는 `Room` 고정, 한글 문서는 "모임" |
| 참여 취소 / 나가기 | **나가기**(`RoomLeave`) | 사용자 문구는 맥락에 따라 다를 수 있으나 코드·이슈는 `leave` |

## 새 용어를 추가할 때

1. 이미 있는 말로 표현되는지 먼저 본다 — 동의어를 늘리지 않는다.
2. 한글·영문 쌍을 정하고 이 표에 한 줄 넣는다.
3. 엔티티·API 필드·이슈 제목에 그 말을 그대로 쓴다.
