# 팀 지식

`docs/conventions/` 가 **규칙**이라면, 여기는 **경험**이다.

컨벤션은 "이렇게 하기로 정했다"를 적는 곳이고, 여기는 "이래서 물렸다 / 이 스택은 이렇게
동작한다"를 적는 곳이다. 규칙으로 못 박기엔 상황 의존적이지만, 모르면 같은 실수를 반복하는 것들.

사람도 읽고, 코딩 에이전트(Claude Code / Codex)와 PR 리뷰 봇도 읽는다.

## 문서

| 문서 | 다루는 것 |
| --- | --- |
| [security.md](security.md) | 인증·인가·비밀값. 우리 스택의 함정과 심각도 기준 |
| [performance.md](performance.md) | 쿼리·인덱스·JPA 로딩. 우리 규모에서 무엇이 근거가 되는가 |

주제가 늘어나면 파일을 추가하고 이 표에 한 줄 넣는다.

## 무엇을 쓰는가

**쓸 것**

- 우리 스택 이 버전의 함정 — "Kotlin은 클래스가 기본 final이라 프록시가 안 걸린다" 같은.
- 실제로 물린 것 — 언제, 무엇이, 어떤 조건에서. 재발을 어디서 막을 수 있는지.
- 우리 팀의 판단 기준 — 무엇이 blocker이고 무엇이 무시해도 되는지.
- 우리 규모에 대한 사실 — 데이터 크기, 트래픽, 아직 측정 안 된 것.

**쓰지 말 것**

- 교과서 지식. "SQL 인젝션이란 무엇인가", "N+1이 왜 느린가" 같은 것.
  사람도 에이전트도 이미 안다. 분량만 늘고, 리뷰 봇은 목록에 있다는 이유로
  실제로 없는 문제를 보고하기 시작한다.
- 규칙. 그건 `docs/conventions/`에 쓴다. 여기 쓰면 두 곳이 갈라진다.

## 어떻게 늘리는가

**장애나 버그가 났을 때 한 줄 추가하는 것**이 이 폴더의 유일한 유지 방법이다.
따로 회고 문서를 만들지 말고 해당 주제 파일의 `## 우리가 겪은 것`에 한 줄 적는다.

```
- 2026-08-11: 룸 참가 API가 동시 요청에서 중복 참가를 허용했다.
  원인: 유니크 제약 없이 조회-후-삽입. 재발 방지: storage.md의 유니크 충돌 매핑 규칙.
```

날짜, 무엇이, 어떤 조건에서, 원인, 어디를 보면 되는지. 다섯 줄이면 충분하다.

## 누가 읽는가

- **사람** — 새로 합류했거나 낯선 영역을 건드릴 때.
- **코딩 에이전트** — 루트 [`CLAUDE.md`](../../CLAUDE.md) / [`AGENTS.md`](../../AGENTS.md)가 여기를 가리킨다.
- **PR 리뷰 봇** — [`.review-swarm.yaml`](../../.review-swarm.yaml)의 `knowledgeFiles`가
  주제별로 해당 전문 에이전트에게만 주입한다.
